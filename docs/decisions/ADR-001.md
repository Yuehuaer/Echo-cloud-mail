# ADR-001: 双域名邮箱部署与 GitHub→Cloudflare 联动方案

## 状态
已接受

## 日期
2026-11-25

## 背景
项目部署在 Cloudflare Workers，需要把第二个邮箱域名 `kechox.com` 加入现有 `229830.xyz` 实例，同时打通 GitHub 代码推送到 CF 的自动部署，并支持两个账号的管理员需求。约束：项目是上游 `maillab/cloud-mail` 的 fork，用户希望尽量不改业务代码；提供的 CF Token 为临时 7 天。

## 决策
1. **联动方式**：使用仓库已有的 GitHub Actions workflow，补齐 Secrets 后启用；不采用 Workers Builds 直连 GitHub。
2. **第二域名**：通过 Secret `DOMAIN` 数组 + CF Email Routing + Resend 多域名 key 实现双域名收信/发信；web 入口用 `CUSTOM_DOMAIN2` 声明第二个自定义域名。
3. **双账号管理员**：不改代码，直接把 `ADMIN` Secret 从 `Yue@229830.xyz` 换成 `Yue@kechox.com`（项目硬编码单账号超管）。
4. **配置存放**：敏感值全部放 GitHub Secrets，不进仓库文件；`.workbuddy/` 本地记忆加入 .gitignore。

## 备选方案
- **方案 A：Workers Builds 直连 GitHub** — 变量留 CF 侧、无 Token 过期问题；但需禁用 Actions、重配构建，改动更大。因沿用现成 workflow 成本更低而未采用。
- **方案 B：改代码支持多超管** — 把 `admin` 改成数组并用 `isAdmin()` 统一判定（约 10 处）；因偏离上游 fork、需重新部署而未采用。
- **方案 C：Cloudflare Email Sending 替代 Resend** — 可免 Resend 配置；但用户已在 Resend 验证域名，复用现有通道成本更低。

## 影响
- **正面**：零业务代码改动（仅 workflow 一处修复）；push main 自动部署；两域名收发信与双 web 入口齐备。
- **负面**：CF Token 临时 7 天，到期需手动换 Secret；超管仍为单账号，原 `Yue@229830.xyz` 降为普通管理员；`CUSTOM_DOMAIN2` 是硬编码 Secret，将来加第三域名需再改 workflow。
